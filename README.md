# 一起去 · 旅行 AA 账本

用 Taro 4.3 + React 18 + TypeScript 开发的微信小程序，适合朋友一起旅行时记录共同开销、均分费用和确认结算。

## 已实现

- 创建旅行、邀请码加入、微信小程序卡片分享邀请；加入时填写朋友认识的名字。
- 总览和旅伴页可填写或修改本人在本旅行的名字，历史账单同步显示，其他旅行昵称与金额保持不变。
- 记录金额、用途、付款人、分摊成员、分类、日期和备注。
- 全员或部分成员均分，实时预览每个人承担的金额。
- 查看、筛选、修改和软删除账单，保留最近的操作记录。
- 查看总消费、分类统计、个人垫付、应承担、待收和待付。
- 生成转账建议；付款人标记已转账，收款人确认后更新余额。
- 待确认转账预留金额，避免再次提示付款；期间仍可以新增消费。
- 结清后关闭账本，创建者可以重新打开补记。
- 记账表单不保存或恢复本机草稿；只有点击保存成功才进入共享账本，当前页面内提交失败可重试。
- 云模式在旅行页面可见时每 15 秒刷新一次，切换页面也会刷新。
- 本地演示账本、添加演示成员、切换身份，方便体验多人流程。

金额全部以整数“分”存储。每笔费用的分摊总额与原金额严格相等，除不尽的尾差按成员 ID 的固定顺序分配。

## 配置真实多人账本

### 1. 微信与云环境

项目已配置小程序 AppID `wxf31f6bf177ee9207`。使用具有该小程序开发权限的微信登录开发者工具，导入项目根目录。在工具顶部打开“云开发”，按提示开通并创建环境，建议名称为 `jiqian`。等待环境初始化完成后，在环境设置中复制完整环境 ID，并确认该环境关联的是此 AppID。

```bash
# 如果 .env.local 不存在，再创建它；已存在时直接修改。
cp .env.example .env.local
```

把 `.env.local` 改为：

```dotenv
TARO_APP_CLOUD_ENV=你的云环境ID
```

这里是环境 ID，不是密钥。修改后重新启动构建。配置云环境后，小程序会明确使用云服务，云服务失败时不会回退到演示账本。

### 2. 数据库

在云开发控制台手动创建三个集合：

| 集合 | 用途 |
| --- | --- |
| `users` | 当前微信用户的昵称 |
| `trips` | 旅行、成员、费用、实际分摊、转账和操作记录 |
| `invites` | 不可预测的邀请码与旅行 ID 的映射 |

每个集合都设置自定义安全规则，内容与 [cloud/database.rules.json](cloud/database.rules.json) 相同：

```json
{ "read": false, "write": false }
```

客户端不直接读写数据库。所有访问经由云函数校验微信身份和旅行成员权限；云函数服务端 SDK 可以访问这些集合。给 `trips` 添加 `memberIds` 升序、`createdAt` 降序的复合索引；如果控制台查询提示创建索引，按提示建立。

### 3. 部署云函数

```bash
npm run build:cloud
npm run build:weapp
```

在微信开发者工具中，右键 `cloudfunctions/ledger` → **上传并部署：云端安装依赖**。选择前面配置的云环境，使用 Node.js 18 或更新的运行环境，超时设为 20 秒。

如果右键菜单没有部署选项，先在 `cloudfunctions` 根目录右键，选择当前云环境。部署后到云开发控制台的“云函数”列表确认能看到 `ledger`，再回到开发者工具重新编译小程序。顶部不再出现“本地演示”提示，说明前端已切换到云模式；能创建旅行并在 `trips` 集合看到记录，说明后端链路正常。

云函数使用微信调用身份，联调请从小程序页面发起操作；控制台直接测试函数可能没有 `OPENID`，这时会返回“请从微信小程序调用”。

若页面仍显示本地演示，检查环境 ID 是否填写并重启 Taro 构建；若提示函数不存在，检查 `ledger` 是否部署到同一个环境；若提示非法环境，检查完整环境 ID 和小程序关联；若提示云服务请求失败，在 `ledger` 调用日志检查集合和索引是否已创建。

`cloud/index.ts` 是源文件，`cloudfunctions/ledger/index.js` 是构建产物。修改业务逻辑后重新运行 `build:cloud` 并部署。

真机验证：A 创建旅行并分享邀请 → B 用自己的微信打开并加入 → A、B 分别记账 → 双方看到相同的账单和余额 → 付款人在微信手动转账后标记 → 收款人核对后确认。

## 账本规则

```text
剩余余额 = 垫付金额 − 应承担金额 + 已确认转出 − 已确认转入
```

正余额表示待收，负余额表示待付。结算转账不是消费，不会增加旅行总开销。转账建议按包含待确认转账的余额计算，因此不会重复提示已经标记的金额。

- 一笔费用一个付款人；多人共同付款可拆成多笔。
- 记录人和付款人可以不同。
- 新加入成员不分摊历史费用。
- 只有记录人或创建者可以修改、删除账单；新版修改和删除校验这笔费用的内容快照，成员改名、加入或新增其他费用不会导致冲突；同一笔被修改时需要核对最新内容，避免覆盖。旧客户端仍使用账本版本校验。
- 有待确认转账时可以新增费用，历史账单要先确认或取消转账标记再修改。
- 只有付款人可以标记自己的转账，只有收款人可以确认。确认后不能直接撤销。
- 只有创建者能移除已结清成员；退出后历史金额保留。被移除的成员不能通过原邀请码自动重新加入。
- 涉及已退出成员的历史账单可以补备注，但不能通过修改或删除使该成员重新出现未结余额。
- 关闭账本需要所有成员余额为零且没有待确认转账。关闭后不允许写入，创建者可重新打开。
- 未提交内容仅存在当前记账页面，离开或重新加载后丢弃；新增账单从空白开始，编辑账单读取已保存内容。旧版本本机草稿不再读取。

第一版采用**一个旅行一个文档**，把旅行修改放入服务端事务中，适合朋友的小规模账本。当前每次旅行最多 30 位成员、500 笔费用（含软删除）、500 条转账记录，文档最多 800 KB；保留最近 200 条操作动态。旅行列表暂时加载最近 20 个账本。后续可拆分集合、增加分页和实时订阅。

当前不包含票据照片、OCR、比例分摊、退款录入和微信支付。转账由大家在微信里手动完成。

```text

  pages/             旅行、总览、记账、账单、旅伴、结算
  components/        通用界面组件
  services/          本地与云服务适配
  store.tsx          React 状态与刷新
shared/
  types.ts           共用数据类型
  ledger.ts          金额校验、均分、余额、转账建议和权限规则
  demo.ts            演示账本
cloud/               云函数 TypeScript 源码
cloudfunctions/      微信开发者工具部署目录
tests/               计算、权限、幂等和模拟事务测试
scripts/             云函数构建、浏览器验证
```
